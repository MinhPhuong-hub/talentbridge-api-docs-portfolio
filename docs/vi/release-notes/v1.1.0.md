# Ghi chú phát hành TalentBridge API v1.1.0

**Ngày phát hành giả lập:** 24/10/2026

Phiên bản v1.1.0 cải thiện quy trình ứng tuyển và tài liệu dành cho nhà phát triển.

## Khả năng tương thích

Trường `coverLetter` không bắt buộc có tính tương thích ngược. Client cũ không cần thay đổi request body vì trường `coverLetter` là tùy chọn; không được suy rộng kết luận này cho mọi thay đổi hành vi. Client cần xử lý rõ phản hồi `409 Conflict` khi ứng tuyển trùng. Đây là **quyết định đã chấp thuận trong hợp đồng API giả lập v1.1** (TB-005), không phải hành vi đã kiểm chứng trên backend thực. Các trường hợp biên vẫn chưa được quyết định.

## Thư ứng tuyển không bắt buộc

Ứng viên có thể gửi thêm trường `coverLetter` (không bắt buộc) khi tạo hồ sơ ứng tuyển.

Ví dụ:

<!-- doc-test: request POST /jobs/{jobId}/applications -->
```json
{
  "coverLetter": "I have three years of experience writing API documentation."
}
```

Thay đổi này tương thích ngược: các client đang tích hợp không bắt buộc gửi trường mới.

## Hồ sơ ứng tuyển trùng lặp

Theo hợp đồng giả lập v1.1, khi cùng một ứng viên nộp hồ sơ lần thứ hai vào cùng một việc làm, API trả về `409 Conflict`. Xem [TB-005](../contract-decision-record.md): xử lý hồ sơ đã rút, cạnh tranh đồng thời và idempotency vẫn chưa được xác định.

Client nên hiểu response này là dấu hiệu hồ sơ đã tồn tại, thay vì tự động gửi lại cùng một request.

## Cải thiện tài liệu

Bản phát hành cũng làm rõ:

- Sự khác biệt giữa lỗi xác thực và lỗi phân quyền.
- Quyền sở hữu khi xem danh sách hồ sơ ứng tuyển.
- Cách sử dụng cursor phân trang.
- Các mã định danh do server tạo.

## Hành động cần thực hiện

Client không cần sửa request body để hỗ trợ trường `coverLetter` tùy chọn, nhưng phải đánh giá tác động của phản hồi `409` mới. Nếu muốn hỗ trợ thư ứng tuyển, client có thể thêm trường `coverLetter` không bắt buộc vào request tạo hồ sơ.
