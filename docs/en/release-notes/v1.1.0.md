# TalentBridge API v1.1.0 release notes

Release date: October 24, 2026

Version 1.1.0 improves the job-application workflow and developer
documentation.

## Compatibility

The optional `coverLetter` field is backward compatible. Existing clients do not need to change their request bodies to omit `coverLetter`. This statement applies only to that optional field, not to all behavioral changes. The duplicate-application `409 Conflict` response is an **approved decision for this fictional v1.1 contract**, recorded as TB-005. It is not verified implementation behavior; edge cases remain open.

## Optional cover letters

Candidates can now include an optional `coverLetter` property when
submitting an application.

Example:

<!-- doc-test: request POST /jobs/{jobId}/applications -->
```json
{
  "coverLetter": "I have three years of experience writing API documentation."
}
```

This change is backward compatible. Existing integrations are not
required to send the new field.

## Duplicate applications

In this fictional v1.1 contract, submitting a second application for the same candidate and job returns:

`409 Conflict`

Clients should treat this response as an indication that an application already exists rather than retrying the same request automatically. See [TB-005](../contract-decision-record.md) for unresolved withdrawn-application, concurrency, and idempotency details.

## Documentation improvements

This release also clarifies:

- authentication and authorization errors
- ownership requirements for viewing job applications
- pagination cursor behavior
- server-generated identifiers

## Action required

No request-shape migration is required for the optional `coverLetter` field. However, clients must review the new duplicate-submission `409` behavior before relying on compatibility.

Clients that want to support cover letters can add the optional
`coverLetter` property to their application request.
